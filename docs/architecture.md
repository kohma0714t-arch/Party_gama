# 技術・通信・物理アーキテクチャ設計書

## 1. システム全体構成
本プロジェクトはバックエンド専用サーバーを必要としない **純粋フロントエンド＋ブラウザ間P2P（ホスト権威・スター型）** アーキテクチャを採用する。

```
[Guest Browser 1..5] ──(WebRTC DataChannel / BroadcastChannel)──▶ [Host Browser (Authority)]
                                                                       │
   ◀── 25Hz SNAPSHOT (補正用状態) + 即時 EVENT (音/演出/遷移) ────────┘
```

- **Host Browser**: ルームを作成したプレイヤー（またはソロ＋Botモードのローカルプレイヤー）。`GameSimulation`（60Hz固定タイムステップ）を唯一保持し、全プレイヤーの入力・ブロック選択・配置・当たり判定・スコア計算を権威的に決定する。
- **Guest Browser**: 操作入力（左右/ジャンプ/ダッシュ/しゃがみ/ダンス）とビルド操作（カーソル位置/選択/配置）をHostへ送信し、Hostから届く25Hzスナップショットを線形補間して60fps描画する。

## 3. 6人P2Pネットワーク設計

### 3.1 ルームID・接続フロー
- ルームコードは視認性が高く誤入力しにくい英大文字・数字5桁（紛らわしい `I, O, 0, 1` を除外した32文字セット）で生成する。
- PeerJSのPeerIDは **`tc-party-${roomCode}`** をホストが使用し、ゲストはPeerJS自動割り当てIDから `peer.connect('tc-party-' + roomCode)` で接続する。
- 招待URLは `${origin}${pathname}?room=${roomCode}` とし、アクセス時に自動で参加入力欄へセットする。
- STUNサーバーには Google Public STUN（`stun:stun.l.google.com:19302`, `stun:stun1.l.google.com:19302`）を設定し、NAT越え成功率を高める。
- 接続完了後、ゲストは `JOIN`（名前・希望キャラ）を送信。ホストは満員（6人）または試合中参加不可を確認し、空きがあれば `WELCOME`（割当 `playerId`, `character`, 現在状態）を返信して全員へ `LOBBY_UPDATE` を配信する。

### 3.2 通信メッセージ一覧
| Type | 方向 | 用途 |
| :--- | :--- | :--- |
| `JOIN` | Guest → Host | 参加要求（ニックネーム） |
| `WELCOME` | Host → Guest | 参加承認・自身の `playerId` 通知・現在ルール |
| `REJECT` | Host → Guest | 満員（6人到達）または進行中による拒否理由（日本語） |
| `LOBBY_UPDATE` | Host → All | ロビーのキャラ変更・ステージ・ルール更新 |
| `INPUT` | Guest → Host | プレイヤー入力ビット／アナログ方向（変化時または30Hz） |
| `CURSOR` | Guest → Host | ビルドフェーズ中のカーソル座標・回転・反転状態 |
| `PICK` | Guest → Host | パーティーボックスの選択インデックス要求 |
| `PLACE` | Guest → Host | ブロック配置座標・回転・反転（フリープレイ時は削除含む） |
| `SNAPSHOT` | Host → All | 25Hzで送るゲーム状態スナップショット（プレイヤー座標・速度・状態・タイマー・動的ブロック・発射体） |
| `EVENT` | Host → All | 即時イベント（フェーズ遷移、配置確定、爆弾破壊、キル発生、ゴール到達、SEトリガー、パーティクル座標） |

### 3.3 同期精度・切断耐性・ローカル検証
- **クライアント補間**: ゲストは直近スナップショットへ向けて `lerp`（距離が120px以上離れた場合はワープ等とみなし即時スナップ）することで、25Hz配信でも60fpsの滑らかな動きを表示する。
- **途中切断耐性**: `onPeerLeave` 発火時、ホストは該当プレイヤーをリストから削除（または離脱扱い）し、`BOX_PICK` や `PLACE` や `ACTION` の「全員完了判定」を即座に再評価する。これにより、誰かがブラウザを閉じてもゲームが停止しない。
- **ローカル検証トランスポート (`BroadcastChannel`)**: 同一マシンの複数タブでオフラインでも6人対戦をテストできるよう、`LocalTransport` が同一インターフェース `INetTransport` を実装する。

## 4. 物理・ギミックアルゴリズム設計

### 4.1 AABB軸分離衝突とライダー追従
1. まず動くプラットフォーム（`moving_platform`, `windmill` 羽根）の位置を時刻 `t` から算出し、直前フレームとの差分 `(dx, dy)` を計算する。
2. 前フレームでその足場の上に立っていたプレイヤーには、物理ステップ前に `(dx, dy)` を加算する（動く足場の上で滑らず一緒に運ばれる）。
3. プレイヤーの入力・重力・扇風機風圧・コンベア加速を速度 `(vx, vy)` に反映する。
4. X軸移動 → X軸AABB衝突解決（めり込み補正と壁接触判定 `onWallLeft / onWallRight`）。
5. Y軸移動 → Y軸AABB衝突解決（接地判定 `onGround`・天井接触判定・バネ跳躍・崩れる足場トリガー）。

### 4.2 ハチミツ（Honey）連結・親子追従アルゴリズム
- ハチミツは「独立して空中に浮く足場」ではなく、**接着剤兼粘着デバフ**として機能する。
- 配置時ルール: 既存ブロック、または動く足場（`moving_platform` / `windmill` 羽根）に重なるか隣接（1タイル以内）していれば配置できる。
- 配置が確定すると、ハチミツ位置および上下左右に隣接する「配置済み非固定ブロック」を探索（BFS）し、その連結成分内に**動く親（`moving_platform` または `windmill` 羽根ID）**が1つだけ存在する場合、連結された子ブロック群すべてに `parentId` と相対オフセット `(offsetX, offsetY)`（風車羽根の場合は角度オフセット）を記録する。
- すでに別の動く親に属しているブロック同士は結合しない（衝突・破綻防止）。
- アクション中、子ブロックのワールド座標は毎フレーム親の位置から更新されるため、**「回転する風車の羽根にくっついたトゲ」や「往復リフトに乗ったクロスボウ」**といった創発的ギミックが成立する。

### 4.3 爆弾（Bomb）3×3破壊アルゴリズム
- 配置フェーズで `bomb` を `(gx, gy)` に置くと、即座に爆発範囲 `[gx - 1, gx + 1] × [gy - 1, gy + 1]` にあるすべての「プレイヤー配置ブロック」を削除する（ステージ固有の `staticPlatforms` は不壊）。
- もし削除対象が `moving_platform`（親）だった場合、紐づいていた子ブロックの `parentId` を解除して現在位置に固定する。
- もし削除対象が `portal` の片方だった場合、対になるもう一方も合わせて撤去して不整合を防ぐ。

### 4.4 簡易Bot AI 設計
1人でも6人パーティを楽しめるよう、ホスト内部で動くBot（`isBot: true`）を実装する。
- **選択 (`BOX_PICK`)**: ラウンド序盤は足場系を優先、中盤以降は罠・射撃・特殊もランダム重み付きでピック。
- **配置 (`PLACE`)**: スタートとゴールを結ぶ経路帯の周辺グリッドをサンプリングし、足場系はギャップ上、罠系は既存足場の上・周辺（自分の足元になりすぎない位置）に配置。
- **操作 (`ACTION`)**: ゴール座標への水平移動を基本とし、前方に段差や穴があればジャンプ、壁に触れたら壁ジャンプ、目の前に危険なトゲ・のこぎり・炎が見えた場合は手前で一時減速またはジャンプ回避を試みる。

## 5. Canvas 2D レンダリングパイプライン

60fpsを安定維持するため、重い `ctx.shadowBlur` は使わず、パス描画とハードシャドウ・キャッシュされた背景グラデーションで描画する。
1. **クリア & ダイナミックカメラ変換**: アクション中は生存プレイヤー全員＋ゴールが画面内に収まるようズーム `1.0 〜 1.18`・パンを指数平滑で追従。ビルド中は全体俯瞰（`1.0x`）。
2. **背景レイヤー**: ステージ別の空・遠景シルエット・動く雲・溶岩グロー。
3. **静的ステージ地形 & スタート/ゴール旗**: 手描き風インク枠＋安全ゾーン表示。
4. **風域・射線・軌道ガイド**: 扇風機の風アニメーション、往復のこぎり/リフトの点線軌道、火炎の予兆。
5. **配置ブロック & ハチミツ**: カテゴリ別デザイン＋ハチミツの黄金の垂れ表現。
6. **発射体 & 動的ハザード**: 矢、跳ねるパック、炎、落下中のトゲブロック、パンチアーム。
7. **動物キャラクター（最大6体）**: スクワッシュ＆ストレッチ、手足アニメーション、向き反転、まばたき、死亡ゴースト、頭上ネームプレート。
8. **ビルドプレビュー & パーティクル**: 他プレイヤーのカーソルアイコン、自分の選択中ブロック半透明ゴースト（緑/赤の配置可否）、爆発/羽/星/土煙パーティクル。
