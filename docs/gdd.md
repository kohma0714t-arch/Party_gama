# ゲームデザイン仕様書 (GDD) — TRICKY CRITTERS（トリッキー・クリッターズ）

## 1. エグゼクティブサマリー
- **ゲームタイトル**: **TRICKY CRITTERS（トリッキー・クリッターズ）**
- **キャッチコピー**: みんなで足場を作り、罠を仕掛け、自分だけが生き残れ！最大6人オンライン・コース自作パーティアクション
- **ジャンル**: 2Dパーティ・プラットフォームアクション（コース共同構築 × 対戦レース）
- **ターゲットプレイヤー**: 友人同士・配信者・オンラインでワイワイ遊べるパーティゲーム好き
- **プラットフォーム**: Webブラウザ（PCキーボード / ゲームパッド対応、Vite + TypeScript + HTML5 Canvas 2D、静的ビルドで即配信可能）
- **プレイ人数**: 2〜6人（ブラウザ間P2P最大6人オンライン対戦 / 同一ブラウザ多窓テスト / フリープレイ）

## 2. コアループ & ゲーム進行

```
[LOBBY: ツリーハウス広場] (キャラ操作・6人集合・ルール/ステージ決定)
        ↓
[BOX_PICK: パーティーボックス] (最大8個のランダムアイテムを早い者勝ちで選択)
        ↓
[PLACE: ビルドフェーズ] (グリッド上に足場・罠・爆弾・ハチミツ等を配置)
        ↓
[COUNTDOWN: 2秒カウント] (位置リセット・一斉スタート準備)
        ↓
[ACTION: レースフェーズ] (全員一斉にゴールを目指す・罠が稼働)
        ↓
[SCORE: ラウンド精算] (Too Easy / No Points 判定・各種ボーナス加算)
        ├── 目標ポイント到達者なし → 次ラウンドへ (BOX_PICK)
        └── 目標ポイント到達 or 最大ラウンド終了 → [PODIUM: 表彰台]
```

### 2.1 自己調整メカニズム（動的均衡ルール）
アルティメットチキンホースの本質である**「簡単すぎても難しすぎても全員0点」**のジレンマを最大6人でも機能するよう採用する。
1. **TOO EASY（全員ゴール）**:
   - 生存した状態でゴールに到達した人数が参加人数と一致する場合（ただし参加人数が2人以上のとき）、全員 **+0.0 pt**。
   - 安全なルートばかり作ると誰も勝てないため、自然と罠や難所が置かれる。
2. **NO POINTS（全員脱落）**:
   - 生存ゴール・死後ゴールともに0人の場合、全員 **+0.0 pt**。
   - 自分のトラップで相手を倒しても「自分がゴールできなければ」ポイントが入らない設計にすることで、クリア不能な理不尽コース化を防ぐ。
3. **1人テスト時（参加者＝1人）の例外**:
   - 1人で操作確認や練習を行う場合に限り、`TOO EASY` 判定を行わずゴール点を付与する。

## 3. スコアシステム & ルール設定

### 3.1 標準配点テーブル
| 項目 | 条件 | 加算ポイント | 設計意図 |
| :--- | :--- | :---: | :--- |
| **ゴール (Goal)** | 生存状態でゴール旗に触れる | **+1.0 pt** | 基本の達成報酬 |
| **1位 (First)** | そのラウンドで最初にゴール到達 | **+0.2 pt** | レースのスピード競争を促す |
| **ソロ (Solo)** | 2人以上参加時、自分だけが唯一ゴール | **+0.6 pt** | 難関コース単独踏破の栄誉 |
| **トラップ (Trap)** | 自分が配置した罠・発射体で他者を撃破（※自身がゴールした場合のみ、または1人撃破ごと） | **+0.2 pt / キル** | 意地悪な罠配置の報酬（本設計では「罠キル発生ラウンドでゴールした本人」または「罠所有者がゴール時」に付与し、全員全滅時は0点） |
| **コイン (Coin)** | コインを回収した状態でゴール到達 | **+0.6 pt** | 危険な寄り道へのハイリスク・ハイリターン |
| **カムバック (Comeback)** | 直前2ラウンド連続0点かつ他者に得点者がいた状態からのゴール | **+0.8 pt** | 逆転機会を作り最後まで白熱させる |
| **ポストモーテム (Post-Mortem)** | 死亡直後（0.45秒以内）に慣性・吹っ飛びでゴール旗に突入 | **+0.6 pt** | ハプニング・笑える奇跡を肯定する |

※ トラップボーナスは「全員ゴール / 全員死亡」以外の有効ラウンドにおいて、自分が置いた罠が他プレイヤーを倒した回数 × +0.2 pt として計算する（自分自身が死亡していても罠が仕事をした演出を重視する場合は有効ラウンドで加算）。本実装では**有効ラウンド（1人以上ゴール＆全員ゴールでない）で罠キル数 × 0.2 pt** を加算し、全員脱落時の理不尽キル稼ぎを防止する。

## 4. グリッド & 物理定数設計（アクションの手触り）

ステージは **1マス = 40px** の厳密なグリッドで構成し、キャラクターの運動能力とブロック寸法を定量的に連動させる。

| 定数名 | 値 | 設計上の意味・検証基準 |
| :--- | :---: | :--- |
| `TILE` | `40 px` | 全ブロック配置の最小単位 |
| `GRID_W × GRID_H` | `40 × 22` | ワールドサイズ `1600 × 880 px`（広々とした16:9構築スペース） |
| `DT` | `1 / 60 s` | 60Hz固定タイムステップ物理 |
| `PLAYER_W × PLAYER_H` | `28 × 36 px` | 1マス（40px）の隙間を余裕を持って通れる横幅・高さ |
| `CROUCH_H` | `22 px` | しゃがみ時は1マス高（40px）のトンネルを通過可能 |
| `GRAVITY` | `1900 px/s²` | 軽すぎず重すぎないテンポの良い落下感 |
| `JUMP_VEL` | `-890 px/s` | 最大到達高度 ≈ **208 px（5.2マス）**。5マス段差を確実に登れる |
| `JUMP_CUT_MULT` | `0.52` | ジャンプボタンを早く離すと上昇速度を減衰（小ジャンプ制御） |
| `WALK_SPEED / SPRINT_SPEED` | `270 / 390 px/s` | ダッシュ併用で横3〜4マスのギャップを跳躍 |
| `WALL_SLIDE_MAX_VY` | `125 px/s` | 壁方向入力でゆっくり滑落し罠のタイミングを計れる |
| `WALL_JUMP_VY / VX` | `-715 / 390 px/s` | 壁ジャンプ1回で約 **134 px（3.35マス）** 上昇 |
| `COYOTE_TIME` | `0.11 s` | 足場から落ちた直後約6〜7フレームのジャンプ救済 |
| `JUMP_BUFFER` | `0.11 s` | 着地直前約6〜7フレームのジャンプ先行入力受付 |
| `HONEY_SPEED_MULT / JUMP_MULT` | `0.42 / 0.55` | ハチミツ付着時の移動・ジャンプ低下倍率 |
| `SPRING_VEL` | `-1220 px/s` | バネ踏破時の大跳躍初速（約9.8マス上昇） |

## 8. ビジュアル & サウンド設計

### 8.1 デザインプラン（カラー・タイポ・レイアウト・視認性）
- **カラーパレット（5色基盤）**:
  - スケッチブック紙面 `#FFFDF7` / 温かみのある背景パネル `#F6EFE2`
  - インク輪郭＆文字 `#231F20`
  - 危険・警告レッド `#E63946` / 火炎オレンジ `#FF7A00`
  - 安全・ゴールグリーン `#2BB673`
  - メインアクションブルー `#2D7FF9` / ハチミツゴールド `#FFB703`
- **タイポグラフィ**: 見出し・数値に丸みと張りのある `Fredoka` + 日本語UI全体に視認性の高い `M PLUS Rounded 1c`。
- **視認性の階層ルール**:
  1. 背景（空・遠くの建物・山）は低彩度・輪郭線なしで奥へ引く。
  2. ステージ基本地形・配置ブロック・キャラはすべて `2.5px` の濃いインク輪郭 `#231F20` で手前へ浮かせる。
  3. 危険要素（トゲ・のこぎり・炎・矢）は赤〜オレンジの高彩度配色で統一し、一目で危険と分かるようにする。
  4. 6人乱戦時でも見失わないよう、キャラ頭上に短い名前タグ＋自分専用「あなた」インジケータを表示する。
- **共通ライブアート＆本家準拠UI刷新（ストア品質仕様）**:
  - **共通アートエンジン (`src/game/artwork.ts`)**: ゲーム本編・パーティーボックス・フリープレイパレット・配置ゴースト・動物ポートレートで同一の描画関数 (`drawItemArtwork` / `drawCharacterArtwork`) を共有し、選ぶ瞬間から本物そのままのデザインとアニメーション（のこぎり回転、火炎噴射、バネ伸縮、パンチ飛び出し、クロスボウ射撃、爆弾火花、ハチミツ垂れ等）を確認できる。
  - **開いたパーティーボックス (`PartyBoxModal`)**: ウッドクラフト木箱＆ガーランド旗の中に動く実物ギミックが並び、ホバーで下部のインスペクタ帯に詳細表示、取得者には動物ポートレート付き「GET!」スタンプが押される。
  - **実物配置プレビュー**: 配置カーソル上でギミック実物（回転・反転・アニメーション）を半透明プレビューし、爆弾の3×3破壊ハイライトや射線・移動軌道も視覚化。
  - **ライブタイトルジオラマ＆クリーンホーム**: タイトル画面背景で6動物と各種ギミックが動き回るリアルタイムデモシーンを描画し、中央上部に木製看板タイトル・中央に縦並び3ボタン（`部屋を作る` / `部屋に入る` / `設定`）のみを配置。各項目から対応する専用モーダル（ルーム作成・参加・音量＆表示設定）を開く。
  - **フルスクリーン表示対応**: タイトル画面・ロビー・設定モーダル・プレイ中HUDからブラウザのフルスクリーン表示（Fullscreen API）をいつでも切り替え可能。
  - **スリムなツリーハウスロビー＆ランダムステージ**: ロビー滞在中は上端のスリムバーのみを表示してプレイスペースを広く保ち、参加者枠・キャラ選択・ステージ選択（`🎲 ランダム`含む）・ルール・フルスクリーン設定を「⚙ ルーム設定」モーダルへ集約。

### 8.2 動的サウンド設計（Web Audio API）
- **動的BGM（128 BPM / 5トラック構成）**:
